# Локальный макет театрального сайта

Проект повторяет структуру https://odinteatr.com/ и предназначен для заполнения собственными текстами и изображениями. Исходный сайт изучен в локальном Chrome через Playwright. Ничего не опубликовано.

## Запуск

```powershell
cd C:\Users\Admin\Projects\website-cloner
npm.cmd run dev
```

Откройте http://localhost:3000. Проверка производственной сборки: `npm.cmd run build`.

## Страницы

- `/` — полноэкранная обложка, баннеры, афиша, особое предложение, меню, контакты, партнёры.
- `/plays` — вертикальные полноширинные блоки спектаклей.
- `/we` — команда, карточки с белой рамкой, переход в профиль.
- `/theatre` — три большие секции с закреплением фона при прокрутке и завершающий фотоблок.
- `/faq` — девять раскрывающихся вопросов.
- `/contacts` — две колонки контактной информации, ссылка на аренду.
- `/arenda` — обложка, состав услуг и условия аренды.
- `/krasnodar1` — резиденция, описание, фотографии, этапы, положение, партнёры и участие.
- 30 адресов спектаклей — обложка, якорная навигация, описание, трейлер, галерея, состав и информация о постановке.
- 21 адрес участников — портрет, биография, ссылки на спектакли и галерея.

Всего 59 маршрутов. Полная таблица: [routes.md](docs/research/odinteatr/routes.md).

## Замена контента

Контент хранится в `content/`: `plays.json` — спектакли, `people.json` — участники, `ui.json` — общие подписи, `site.json` — общие данные, `pages.json` — тексты остальных разделов, `checkout.json` — оплата. Подробная инструкция: [content/README.md](content/README.md).

- `brand`, `phone`, `email`, `address`, `hours` — общие данные.
- `intro` — демонстрационный текст информационных секций.
- `media.homeHero`, `media.promos`, `media.theatre`, `media.rental`, `media.residence` — изображения общих разделов.
- `plays.json`: `title`, `subtitle`, `description`, `image`, `gallery`, `about`, `cast`, `ageRating`, `scheduleLabel` — данные спектаклей.
- `people.json`: `name`, `role`, `bio`, `image`, `gallery`, `playSlugs` — данные участников.
- `faq` — вопросы и ответы. `media: true` включает место для изображения подарочного билета.
- `slug` задаёт адрес страницы. При изменении адресов обновите ссылки при необходимости.
- `sourceTitle` — служебная подпись для сопоставления спектакля с исходной страницей, на сайте не отображается.

Сложите свои файлы в `public/sites/odinteatr/`. Например, файл `public/sites/odinteatr/poster.jpg` задаётся как `"image": "/sites/odinteatr/poster.jpg"`. Пустая строка включает нейтральную заглушку. В `gallery` добавляйте пути к фотографиям в порядке показа; раскладка автоматически чередует один большой кадр и два маленьких. Галерея открывается в отдельном окне с переключением фотографий.

Общие подписи, заголовки разделов спектаклей и участников, кнопки и навигация редактируются в `content/ui.json`. Тексты остальных разделов находятся в `content/pages.json`, тексты оплаты и демонстрационный заказ — в `content/checkout.json`. Все размеры, цвета и адаптивные правила — в `src/app/globals.css`. Шрифт Oswald хранится локально вместе с лицензией в `public/sites/odinteatr/fonts/`.

## Границы макета

Оригинальные фотографии, видео, имена, контакты и логотипы заменены заглушками. На главной сохранено место под внешний виджет афиши: реальная продажа билетов не подключена, кнопки открывают локальное информационное окно. Ссылки социальных сетей направлены на локальные контакты до добавления собственных адресов. Страницы спектаклей и участников реализованы через общие шаблоны; индивидуальные художественные вариации каждой из 51 исходных детальных страниц не воспроизводились отдельно. Для исследованных страниц `/pahlava_gluposti` и `/kukuruzazhe` уточнены количество и геометрия фотоблоков.

## Проверки и материалы

`npm.cmd run check` выполняет ESLint, TypeScript и производственную сборку.

Снимки исходных и локальных страниц на 1440×1000 и 390×844, измерения и отчёт браузерных проверок находятся в `docs/research/odinteatr/`. Дополнительно проверена ширина 1920. Проверены переходы, аккордеон, карусель, открытие/закрытие окна билетов, просмотр галереи и отсутствие горизонтального переполнения. Проверки HTTP охватывают все 59 маршрутов; браузерный осмотр охватывает основные разделы и типовые детальные страницы.

Вспомогательные скрипты анализа используют Playwright из `C:\Users\Admin\Projects\.tools\browser` и установленный Chrome. Для запуска самого сайта эти инструменты не нужны.
